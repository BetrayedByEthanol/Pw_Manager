# V02-L-A/B — Native FIDO2 Negative Verification & Safe Physical Failure Probes

**Status: review-only implementation candidate.** No physical execution occurs in CI or in this PR. Local hardware tests require the operator's existing V02-J/K private synthetic test session and explicit confirmation. This milestone protects conventional password entries; it does not implement passkeys. WebAuthn PRF parity (I-P05) is a separate future experiment.

## Scope

- **A: native verifier negatives.** Obtain one fresh native UV-requested CTAP test assertion using V02-J/libfido2; verify its signed RP/challenge/UP/UV under the test public key; then submit altered public signed-transcript fields to local fido2-assert -V -h -p -v. Cases: wrong challenge, wrong RP, modified authenticator data, mutated signature and wrong public key. Extra fail-closed parser tests reject missing signed UP/UV flags, wrong RP hash and malformed authenticator data. **These synthetic flag mutations do NOT establish a real signed UV-absent authenticator response.**
- **B: wrong-device with positive controls.** A known control token proves it can verify its own synthetic credential before and after an attempt to use another test credential. A negative native acquisition is LOCAL_DEVICE_REJECTION_UNCLASSIFIED, not proof of why it failed or of distinct physical keys. Unexpected acceptance is a failure.
- **B: absent-device path precheck.** Refuse a specified absent /dev/hidrawN path without opening any token; this is LOCAL_PRECHECK_REJECTED, **not** an implemented daemon fail-closed test.
- **Offline CI negatives.** Mock verifier failure, timeout, rejected malformed input, missing UV/UP, unexpected verification acceptance, credential/role mismatch, missing device, CI/TTY/root refusal and receipt redaction. No real hardware in CI.

See tools/hardware/fido2_v02l.py and tools/hardware/test_fido2_v02l.py. Existing V02-J functions perform the native operation. No VMK, VERS, DEK, Vaulty entry route or production authenticator is created.

## libfido2 CBOR representation (Codex P1 correction)

`fido2-assert -G` encodes its third output line as **base64 of a CBOR
byte string**, not base64 of raw authenticator-data bytes. A standard
37-byte WebAuthn authenticator-data payload is therefore represented as
`58 25` followed by the 37 raw bytes. V02-L decodes **exactly one
definite, minimal CBOR byte string**, rejects trailing/truncated/noncanonical
wrappers, and checks the RP hash and UP/UV flag positions on the **decoded
payload**. It continues to pass the **original CBOR-encoded base64 third
line unchanged** to `fido2-assert -V` for cryptographic verification.
See [synthetic genuine-CLI-format fixture](../../tools/hardware/fixtures/v02l_libfido2_cbor_authdata.txt)
and the regression tests. The fixture has only synthetic RP/flags/counter,
not a real signature or token output.

## Safety and evidence

1. Explicit --hardware-test, non-root Linux interactive terminal, CI refusal, selected direct character-device /dev/hidrawN, clean Git source and exact operator TEST confirmation. No automatic device selection.
2. Use only private test session.json generated by V02-J/K, not a real account or password. Receipts go to mode-0700 directories outside the repository as mode-0600 files. Failed or interrupted runs leave an INCOMPLETE receipt when initialization has completed.
3. The native PRF result is used only transiently by the prior V02-J Python/libfido2 process, wiped on best-effort mutable-buffer paths, and NEVER written to the receipt. Python and external CLI buffers do not guarantee full zeroization. Only publish the redacted receipt, NEVER private session.json, raw assertions, public test credentials, PIN, challenge, PRF bytes, device paths, RP or token serials.
4. A negative verifier label counts only after a positive signed UV/UP verifier control. A nonzero verifier return for altered public fields is LOCAL_VERIFIER_REJECTED; timeouts/tool errors are INDETERMINATE and unexpected acceptance is UNEXPECTEDLY_ACCEPTED. These are unsigned operator observations, not independent cryptographic results.
5. A previously valid assertion might pass a stateless signature verification if replayed unchanged. The harness only tests a *wrong/fresh challenge*; full runtime replay tracking, registry/revocation and no-fallback controls do not exist in V03/V06 yet. Hardware missing-UV/UP assertion, wrong PIN, retry exhaustion, PIN reset, malicious browser origin and physically forced disconnect are NOT exercised.
6. EV-023 recorded two *operator-reported* YubiKey 5 NFC USB-A devices, firmware 5.7.4. This tool cannot independently establish device uniqueness, manufacturer attestation-chain trust, firmware or token-side UV behavior.

## Local runbook — operator's Linux computer only

Use a clean clone of the V02-L PR branch. Keep the private V02-K session from the previous successful run. Do not share its path/content or any token serial/PIN. Replace all example HID paths after running fido2-token -L. A backup swapped into the same port may reuse the HID path.

~~~sh
git status --short
python3 -B -I tools/hardware/fido2_v02l.py preflight
fido2-token -L

# Replace with the actual private V02-K session you retained.
SESSION="$HOME/.local/state/vaulty-v02k/run-REPLACE-ME/session.json"
install -d -m 700 "$HOME/.local/state/vaulty-v02l"

# Insert PRIMARY, supply only correct PIN/touch as requested.
python3 -B -I tools/hardware/fido2_v02l.py verifier \
  --session "$SESSION" --role primary --device /dev/hidraw0 \
  --receipt "$HOME/.local/state/vaulty-v02l/primary-verifier.json" --hardware-test

# Insert BACKUP, re-check its actual HID path.
python3 -B -I tools/hardware/fido2_v02l.py verifier \
  --session "$SESSION" --role backup --device /dev/hidraw1 \
  --receipt "$HOME/.local/state/vaulty-v02l/backup-verifier.json" --hardware-test

# Keep BACKUP connected: backup positive control, attempt PRIMARY credential
# on backup, then backup positive control again. Never submit an incorrect PIN.
python3 -B -I tools/hardware/fido2_v02l.py wrong-device \
  --session "$SESSION" --role primary --control-role backup \
  --device /dev/hidraw1 \
  --receipt "$HOME/.local/state/vaulty-v02l/wrong-device.json" --hardware-test

# OPTIONAL precheck only, with a path definitely absent on your machine:
python3 -B -I tools/hardware/fido2_v02l.py unavailable \
  --device /dev/hidraw99999 \
  --receipt "$HOME/.local/state/vaulty-v02l/absent-precheck.json" --hardware-test
~~~

All test commands require a fresh receipt pathname and exact TEST confirmation. Do not use sudo or record the terminal. If the V02-K private session was discarded, rerun V02-K with new TEST credentials to recreate one before using V02-L; no actual Vaulty entry is involved. A wrong-key failure after positive controls is still an unclassified device rejection, not proof of two physical devices or trusted per-entry registration.

Offline tests (no physical key):

~~~sh
python3 -m unittest discover -s tools/hardware -p 'test_*.py' -v
python3 -B -I tools/hardware/fido2_v02l.py preflight
python3 tools/v02_verifier/review_bundle.py --write /tmp/v02l-review.json
python3 tools/v02_verifier/review_bundle.py --check /tmp/v02l-review.json
~~~
